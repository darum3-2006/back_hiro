# ユーザー Excel 同期 設計メモ

Excel ファイルを取り込んでテナントのユーザーを同期する（ファイル取り込み → プレビュー → 実行）。

ステータス: 実装済み（2026-08-28）。

## 背景・目的

- ユーザーの入退社を Excel（人事側の名簿など）を正としてまとめて反映したい。
- 「同期」なので追加だけでなく、ファイルに載っていないユーザーの削除、削除済みユーザーの復活も扱う。
- 論理削除の仕組みは導入済み（[USER_SOFT_DELETE.md](USER_SOFT_DELETE.md)）。本機能の「復活」は
  同メモで「運用対応（DB 直接操作）」とされていた復元の、最初の正式な経路になる。

## Excel 形式

- **`.xlsx` のみ**対応（CSV は必要になったら後付け）。1 シート目を読む（シート名は不問）。
- 1 行目はヘッダ、2 行目以降がデータ。

| 列 | 内容 | 必須 | 備考 |
| --- | --- | --- | --- |
| A | メールアドレス | ○ | 同期キー（テナント内一意） |
| B | 氏名 | ○ | 新規追加時のみ使用 |
| C | ロール | - | `admin` / `power_user` / `member` / `readonly`。大文字小文字不問・前後空白トリム |

- ロール列が**有効値ならその値を優先**、空欄・無効値なら取り込み画面で選んだデフォルトロールを適用。
  無効値（typo 等）は黙って無視せず、プレビューで「無効なロール値 `menber` → デフォルトの `member` を適用」のように警告表示する。

## 取り込み画面

- テナント admin 専用（ユーザー管理画面の一機能として配置）。
- ファイル選択に加えて以下を選択する。いずれも**新規追加にのみ適用されるデフォルト値**:
  - デフォルトロール（ロール列が空欄・無効の行に適用）
  - プロジェクト（複数選択可。`user_project_access` に付与）

## 差分タイプ

メールアドレス（trim + lowercase）をキーに、ファイルと DB の全ユーザー（削除済み含む）を突き合わせる。

| タイプ | 条件 | 実行時の処理 |
| --- | --- | --- |
| 新規追加 | ファイルにあり、DB に存在しない | ユーザー作成 + 画面選択プロジェクトの `user_project_access` 付与 |
| 復活 | ファイルにあり、論理削除済みユーザーと一致 | `deleted_at` を NULL に戻す**だけ** |
| 削除 | ファイルになく、有効ユーザーが存在 | `softRemove()`（論理削除） |
| 変更なし | ファイルにあり、有効ユーザーが存在 | 何もしない |
| エラー | 行として不正（後述） | スキップ |

### 既存ユーザーは上書きしない

- 既存（変更なし）ユーザーの**ロール・氏名は上書きしない**。差分タイプ「更新」は設けない。
  既存ユーザーの属性変更は従来どおり画面から個別に行う。
  ただし黙って無視すると気づけないため、ファイルと DB で氏名・ロールが異なる場合は
  「異なりますが上書きしません」の警告をプレビューに出す。
- `is_active`（無効化フラグ）は**現時点で未実装**（[USER_SOFT_DELETE.md](USER_SOFT_DELETE.md) に
  記載があるが、実際には導入されていない）。導入された場合も同期では触らない方針
  （無効化は画面からの個別管理）。

### 復活は状態復元のみ

- ロール・氏名・パスワード・プロジェクト権限はすべて**削除前のまま**戻す。Excel のロール列や画面選択の
  プロジェクトは適用しない。権限調整が必要なら復活後に個別で行う。
- これは「復元 = `deleted_at` を NULL に戻すだけで削除前の状態に完全に戻る」という
  [USER_SOFT_DELETE.md](USER_SOFT_DELETE.md) の設計（周辺データは削除時に消さない）にそのまま乗る。

### 新規ユーザーの初期パスワード

- **ランダム生成し、誰にも表示しない**（実質パスワードログイン不可で払い出す）。
- Google ログインが email 一致で `google_sub` を自動紐づけするため（`auth.service.ts`）、
  新規ユーザーはパスワード配布なしで初回から Google SSO でログインできる。
- パスワードログインが必要なユーザーだけ、管理者が画面からパスワードを設定する。
- Excel に平文パスワード列は設けない（平文入りファイルが社内を回るリスクを避ける）。

## エラー行と保護ルール

### エラー行（実行はブロックしない）

以下の行は「エラー」タイプとしてプレビューに警告表示し、実行時はスキップする。
エラー行があっても他の行は実行できる（厳格ブロックはしない）:

- 氏名が空欄
- メールアドレス形式が不正
- ファイル内でメールアドレス重複（最初の行を採用し、2 行目以降をエラー扱い）

**安全策**: エラー行のメールアドレスが既存ユーザーと一致する場合、そのユーザーは**削除対象にしない**
（行が壊れているだけで「ファイルに載っていない」わけではないため、在籍扱いにする）。

### 削除の保護（スキップして理由表示）

ファイルに載っていなくても以下は削除せず、プレビューで「保護のためスキップ」と表示する:

- **実行者自身**
- **最後の有効な admin**（削除すると admin が 0 になる場合）

## プレビュー画面

- **全件表示**（変更なしも含む）。差分タイプ別フィルタ + 各タイプの件数バッジ。
- **行ごとにカスタマイズできる**:
  - 全行: 適用 ON/OFF チェックボックス（外した行はスキップ。「この人はまだ削除しない」等）
  - 新規追加行: ロール・プロジェクトを行単位で編集可（画面選択はあくまで一括デフォルト）

## API・処理の流れ

xlsx のパースは**フロントで行う**（SheetJS 等）。ファイル自体はサーバに送らない。

1. `POST /users/sync/preview` — パースした行データ（JSON）+ デフォルトロール/プロジェクトを送信。
   サーバが差分（タイプ・警告・保護スキップ）を計算して返す。
2. プレビュー画面で行ごとの ON/OFF・新規行の編集を行う。
3. `POST /users/sync/execute` — **プレビューで確定した行ごとのアクション一覧**を送信。
   サーバは適用前に再検証を行い、通った行だけ適用する:
   - 新規: 同メールが（削除済み含め）まだ存在しないこと
   - 復活: 対象がまだ削除済みであること
   - 削除: 対象がまだ有効であること + 保護ルール（実行者自身・最後の admin）の再チェック
   - プレビュー後に他の管理者の操作等で状態が変わっていた行はスキップし、結果で報告する
     （プレビュー結果を盲信しない）
4. 実行結果画面: タイプ別の処理件数サマリ + スキップされた行とその理由。

- 両エンドポイントともテナント admin 専用。`tenant_id` は JWT 由来の `user.tenantId` でスコープ。
- 実行は 1 トランザクションで行う必要はない（行単位で独立。部分成功を許容し結果で報告する）。

## 決定事項の経緯（要件ヒアリング結果）

| 論点 | 決定 |
| --- | --- |
| 同期キー | メールアドレス（テナント内一意・ログイン ID） |
| 削除の定義 | ファイルに載っていない有効ユーザーを論理削除する完全同期 |
| 既存ユーザーの属性 | ロール・氏名とも上書きしない（「更新」タイプなし） |
| ロール列 | 有効値なら画面選択より優先。空欄・無効はデフォルト適用 + 警告 |
| 復活 | `deleted_at` NULL のみ。削除前の状態を完全維持 |
| 初期パスワード | ランダム生成・非表示。Google SSO 前提 |
| 無効ユーザー | `is_active` は未実装。導入時も同期では触らない |
| エラー行 | スキップして実行可。該当メールの既存ユーザーは削除保護 |
| プレビュー | 変更なしも全件表示 + タイプ別フィルタ + 行単位カスタマイズ |

## 実装メモ

- nest 側:
  - `users/user-sync.service.ts` — プレビュー（差分計算）と実行。ユニットテストあり
  - `users/dto/sync-users.dto.ts` — 行データ / アクションの DTO（最大 2000 行）
  - `users.controller.ts` — `POST /users/sync/preview` / `POST /users/sync/execute`（`AdminGuard`）
  - `projects/project-access.service.ts` — プロジェクト存在検証を `assertProjectsInTenant()` に切り出し
  - migration 不要（既存テーブルのみ使用）
- nuxt 側:
  - `pages/[tenantKey]/settings/user-sync.vue` — 取り込み → プレビュー → 結果の 3 ステップ画面。
    xlsx のパースはフロント（SheetJS `xlsx@0.18.5`、nest の migrate スクリプトと同じもの）。
    テンプレート xlsx のダウンロードもこの画面から
  - `api/users.ts` — `apiPreviewUserSync` / `apiExecuteUserSync`
  - ユーザー管理画面のヘッダに「Excel 同期」ボタンで導線
  - `types/master.ts` の `UserRole` に欠けていた `readonly` を追加（既存バグ修正）
