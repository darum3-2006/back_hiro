# サブタスク機能 設計メモ

大きめのタスクを「束ね役」とし、実作業を子（サブタスク）に分解する。チームの「今週やること」を一覧で回せるようにするのが主目的。

ステータス: 要件確定済み・実装着手前（2026-06-30 時点）。

## 方針の要約

- **子は軽量レコード**（フルタスクではない）。自由なステータス・優先度・タグ・コメントは持たせない。
- **親は従来どおりのフルタスク**。子を持つ親は “束ね役”（自分では作業しない前提）。
- 整合性は **「親完了は子全完了が前提」だけハード**、他はソフト（警告・表示）。
- 子が顔を出すのは **①親タスク詳細の「サブタスク」欄** と **②タスク一覧（今週運用の場）** の 2 か所に限定。ボード/ガント/カンバン/検索/通知は初期は対象外。

## データモデル

`comments` と同じ作法で **`project_id` でスコープ**し、`task_id` で親を参照する。`tenant_id` は持たず、`project → tenant` 経由でスコープする（Service/Controller では親タスクが自テナント・自プロジェクトに属することを必ず検証）。

### `subtasks` テーブル

| カラム | 型 | 備考 |
| --- | --- | --- |
| `id` | uuid PK | |
| `project_id` | varchar(36) FK→`projects` | `ON DELETE CASCADE`。一覧（プロジェクト横断の今週集計）用にも使う |
| `task_id` | varchar(36) FK→`tasks` | 親タスク。`ON DELETE CASCADE`（**親削除で子も削除**） |
| `title` | varchar(255) | サブタスク名 |
| `assignee_member_id` | varchar(36) FK→`project_members`, nullable | 担当（任意）。`ON DELETE SET NULL` |
| `deadline` | date, nullable | 期限（任意）。Entity では `Date`、操作時のみ dayjs |
| `memo` | text, nullable | フリーテキストのメモ。**Markdown 対応**（説明欄・コメントと統一）。表示は既存 `renderMarkdown` / `MarkdownContent`、入力は `MarkdownEditor` を流用 |
| `done` | boolean | 完了フラグ（既定 false） |
| `completed_at` | datetime(6), nullable | done になった日時（履歴・表示用） |
| `position` | int | 親内の並び順 |
| `created_at` / `updated_at` / `deleted_at` | | `BaseEntity` 共通基底 |

- **1 段のみ**（孫なし）。`subtasks` は他の `subtasks` を子に持たない。
- **同一プロジェクト内**（`project_id` は親タスクの `project_id` と一致）。
- 子は独自の `seq` / 短縮コードを持たない（住所は親の中）。

## 整合性ルール

不変条件: **親が終端ステータス（`is_terminal = true`）⇒ その親の子は全完了**。終端は完了・却下など区別せず**すべてに適用**（`is_terminal` だけで判定。マスタ拡張は不要）。

### ハード（拒否する）

1. **親 → 終端ステータスへの変更**: 未完了の子が 1 件でもあれば拒否（`BadRequestException`「未完了のサブタスクが N 件あります」）。フロントでも終端ステータスを選べないよう無効化し理由を表示。
2. **親が終端のとき**: 子の追加／完了解除（done→未）を拒否（「先に親のステータスを戻してください」）。**自動で親を戻す挙動は入れない**（勝手な状態変更・通知の多発を避ける）。
3. **一括編集**: 未完了の子を持つ親を終端にしようとした分は**スキップ**し、結果に「N 件はサブタスク未完了でスキップ」を表示。

### ソフト（気づかせるだけ）

- 子の期限が親の期限を超過 → ⚠ アイコンで警告のみ（ブロックしない）。
- 進捗「2/4」を親タスク詳細と一覧バッジに表示。
- 自動連動（全子完了で親を自動完了 等）は**しない**。

### 変更履歴（案B: 親タスクの監査ログに相乗り）

- サブタスクの **追加 / 完了・未完了 / 削除** を親タスクの `audit_logs`（`entity_type='task'`, `action='update'`）に記録し、親詳細の「コメント・履歴」タイムラインに表示する。
- `changes[].field` は `subtask_added` / `subtask_completed` / `subtask_reopened` / `subtask_deleted`。フロントの `describeAuditChange` が「サブタスク「◯◯」を追加/完了/未完了に戻した/削除」と整形する。

### 通知

- **Slack**：サブタスクの**追加**は親プロジェクトの「新しいタスクが登録されたとき」トグル、**完了**は「タスクが完了したとき」トグルに相乗りして送信（メッセージは親タスクへのリンク付き）。未完了に戻す・削除・担当変更は Slack 送信しない。
- **アプリ内**：サブタスクの**担当に設定/変更**されたユーザーへ通知（既存の `assigned` タイプを流用、操作者本人は除外、通知は親タスクに紐付く）。追加・完了はアプリ内通知しない。
- いずれもトランザクション外のベストエフォート（送信失敗してもサブタスク操作は成立）。
- **タイトル・担当・期限・メモの編集は履歴に残さない**（運用ノイズを避ける）。

## 表示

### ① 親タスク詳細（スライドオーバー）の「サブタスク」欄 — 子の住所

- 追加・編集・並び替え・完了チェックを行う場所。
- 行: 完了チェック / タイトル / 担当 / 期限 / メモ（展開 or 編集時）/ ⚠（親期限超過時）。
- ヘッダに進捗「2/4 完了」。

```
サブタスク   2/4 完了                 [＋ 追加]
☑ 設計レビュー        山田   〜6/20
☑ API実装            佐藤   〜6/25   📝
☐ 結合テスト          鈴木   〜7/02  ⚠ 親期限(6/30)超過
☐ ドキュメント        —      —
```

### ② タスク一覧（今週/チーム運用の場）

- 子を**実作業の行として表示**。各行に親名をパンくず（`#12 決済 › 結合テスト`）。
- **子を持つ親は独立行として出さない**（束ね役なのでノイズになる）。子のないタスクは従来どおり 1 行。
- 件数は子でカウント。
- メモは一覧には出さない（Markdown のため。必要なら 📝 アイコンのみ）。
- 子クリック → 親詳細の「サブタスク」欄へ（その場で完了チェックも可）。

```
今週（チーム）
#12 決済 › 結合テスト        鈴木  ☐  〜7/02
#12 決済 › ドキュメント      佐藤  ☐  〜7/03
#8  検索改善 › 仕様確認      山田  ☐  〜7/01
#20 バグ修正                田中  ☐  〜6/30   ← 子のない親はそのまま1行
```

- 子の行はフルタスク行より列が少ない（ステータス/優先度/タグ無し）→ **縮約行で描画**（それらの列は「—」）。
- 子行の完了チェックはその場でトグル可（インライン更新）。担当・期限は表示のみ（編集は親詳細で）。

### 一覧の確定仕様（案X: 常に子を表示）

- **表示対象** = 子を持たないタスク ＋ 全サブタスク。子を持つ親タスクは非表示。データは `GET /projects/:projectId/subtasks`（親 seq/content 付き）で取得しフロントでマージ。
- **ソート**：表示行のフラット。期限・担当・内容は子も値を持つので普通に効く。**No ソートは子に親タスクの seq を持たせ、親の位置に子がまとまる**（親行は畳まれて出ないため自然に収まる。同一親の子同士は並び順のまま）。子が持たない列（ステータス/優先度/タグ）でソートしたときは、子は「値なし」として**末尾**に固める。
- **フィルタ**：担当 / 期限(範囲) / 検索（子タイトル・親名・#親seq）は子にも適用。ステータス / 優先度 / タグ / フラグ / deadline 以外の日付範囲 が有効なときは**子を除外**。「完了も表示」OFF なら done 済みの子は隠す。
- **件数**：表示行（タスク＋子）でカウント。
- **一括編集**：子は選択対象外（チェックボックスはタスク行のみ）。
- **クリック**：子のタイトルで親詳細を開く（親は seq で解決。一覧に親行が無くても全タスク配列から引ける）。

## 権限

- 子の作成・編集・削除・完了チェックは**プロジェクトメンバー誰でも**（インライン編集と同じ粒度）。
- スコープは親タスク経由で担保（親が自テナント・自プロジェクトであることを検証）。

## 対象外（初期リリース）

ガント / カンバン / グローバル検索 は子を扱わない（親のみ）。担当ベースの個人集計（ホームの「自分のタスク」）への波及も将来検討。

（実装済み・上記「通知」参照）: 一覧の子行表示（案X）、ボードのカードにサブタスク進捗バッジ＋バー、Slack（追加・完了）、アプリ内通知（担当設定）。

## 実装メモ（要件ではなく作業項目）

- **バックエンド**: `subtasks` モジュール（Entity / Service / Controller / DTO / マイグレーション）。
  - エンドポイント案: `GET/POST /projects/:projectId/tasks/:taskId/subtasks`、`PATCH/DELETE …/subtasks/:id`、並び替え用の `PATCH …/subtasks/reorder`。
  - 親完了ガードは `TasksService.update`（終端遷移時に子の未完了を確認）と subtasks の追加/完了解除時の双方に入れる。
  - 一括編集（`TasksService.bulkUpdate`）はサブタスク未完了の親をスキップ（既存の NotFound スキップと同様に新例外を捕捉）。
  - 一覧 API は子を行として返す形を検討（親をパンくず化、子を持つ親は親行を出さない）。縮約行のための DTO 形を決める。
- **フロント**: 親詳細に「サブタスク」欄コンポーネント（メモは `MarkdownEditor`/`MarkdownContent`）、一覧の子行（縮約）描画、進捗バッジ、⚠ 警告、終端ステータスの無効化＋理由表示。
- 一覧での子行の見せ方が最大の作り込みポイント。実装は早めにモックで確認しながら進める。
